Mabi: the Northbridge University IT Desk assistant

An AI help-desk chat for a (fictional) university, built on open-source LibreChat, running on AWS, and run like a real service: watched, backed up, locked down and able to fix itself.

Recorded presentation (5–8 minutes): the reskin, the running system in AWS, the dashboard and alarms, the restore and the fault.

What the system does

Students and staff of Northbridge University open https://d2f1g5u307k6aa.cloudfront.net, log in and ask Mabi everyday IT questions: "I forgot my password", "How do I connect my phone to the Wi-Fi?", "How much is a colour print?". Mabi answers in English, Filipino or Taglish, using only the IT Desk's own information. It refuses things it must not do: it never repeats a password, cannot reset accounts, and sends grade questions to the Registrar.

What was wrong with how it was run

The starting point was LibreChat as it comes out of the box, on a laptop. It only worked while the laptop was on. Anyone who could reach it could create an account. The AI key sat in a plain text file. Nothing recorded whether it was working, nobody would be told if it broke, and if the laptop died every conversation was gone. The first copy on AWS was no better: it was reachable over plain HTTP at a raw IP address, with the web port open to the whole internet.

What I changed

  • Made it ours: new name, logo, colours, wording and safety rules; six invented IT Desk documents kept in Amazon S3.
  • Put it on AWS properly: one small server behind Amazon CloudFront (HTTPS), the server only accepts traffic from CloudFront, no SSH, sign-up closed, the AI key in Parameter Store.
  • Watched it: every question logged with its time, outcome and version; a dashboard; 9 alarms that email a real inbox.
  • Backed it up: nightly database backup to S3, and a restore test that brought the chats back in 43 seconds.
  • Broke it on purpose and fixed it: stopped the app, timed how long the alarm took to notice, wrote a runbook, then added an auto-heal job so the same fault now fixes itself.

What improved

13 min 29 s → 1 min 38 soutage when the app stops (same fault, before and after auto-heal, 2026-11-17)
never → 10 mintime for someone to find out the site is down (no monitoring before; alarm email after)
none → 43 sbackups: none before; nightly to S3 now, restore tested 2026-11-17
10 / 10test questions correct on the live system, 18 Nov (first run on the laptop: 9 / 10, one honest failure)

The trade-off I chose: reliability and operations over cost of redundancy. Everything runs on one t3.small in one zone to stay on the AWS Free plan, so a whole-server failure would still take Mabi down. I accepted that and made recovery fast and tested instead. See the Well-Architected review.
