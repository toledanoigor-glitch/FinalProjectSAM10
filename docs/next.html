What I would do next

In priority order, with the reason each one is where it is.

  1. Put AWS WAF in front of CloudFront with the managed common rules and a rate limit on /api/auth/login and /api/ask. It is the gap ranked first in the Well-Architected review: one script could guess passwords or burn the free model quota and take Mabi down for everyone. A few clicks, a few dollars a month.
  2. Guard against "invented certainty" and measure it properly. Q10 failed on one model and passed on the next, which shows how fragile it is. Add a rule and examples telling Mabi to say "I don't have that information" when the documents are silent, then grow the 10 questions into 30+ labelled ones with a script that asks them through the API every night and publishes the pass rate as a CloudWatch metric with its own alarm.
  3. Deploy automatically from git. A GitHub Action that, on a push to main, runs start-mabi.sh on the server through SSM Run Command (no SSH), so a change is tested and rolled out the same way every time.
  4. Shrink the RPO and rehearse a full rebuild. Back up every 4 hours instead of nightly, turn on EBS snapshots with Data Lifecycle Manager, and actually time a rebuild on a fresh instance from git + S3 to turn the estimated 20–30 minutes into a measured number.
  5. Stop logging secrets and close the inside gaps. Test Q8 showed a typed password ends up in my own CloudWatch request log, so mask password-like text in request_metrics.py before logging. Then give MongoDB a username and password, encrypt the CloudFront-to-server hop, tag every resource for cost allocation, and stop the server overnight with an EventBridge schedule when nobody is using it.
